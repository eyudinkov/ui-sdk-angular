# P0.4: Angular in the playground

The shared playground compiles Angular beside the other four framework plugins. `?fixture=tabs&framework=angular` renders an empty Angular component, and the Tabs spec still passes on `react`, `vue`, `svelte`, `solid` and `web`.

## Settled

- **The trust policy exempts two locked versions.** `trustPolicyExclude` in `pnpm-workspace.yaml` names `semver@6.3.1` and `chokidar@4.0.3`, on the owner's decision. Both are in upstream's lockfile, and `trustPolicy: no-downgrade` stops any install that resolves them again: on the untouched tree, a resolution from no lockfile fails on `chokidar@4.0.3`. Every install that added Angular's builder met `semver@6.3.1`. No other version needed an exemption.
- **`@angular/build` is a dependency of the playground.** `@analogjs/vite-plugin-angular` 2.9.7 calls `require("@angular/build/private")` as it loads, though its `package.json` marks that peer optional.
- **Two overrides hold Angular's builder to the repo's Vite and rolldown.** `@angular/build` pins `vite` 8.3.8 and `rolldown` 1.3.1. Without the overrides, pnpm put those copies under `vitest`, `nuxt`, `@nuxt/kit`, `unplugin`, `vue-router` and a dozen more, and added 301 packages. With them the lockfile has one Vite, 8.3.3, and one rolldown, 1.2.12, and 195 new packages.
- **No root Babel pin.** A root `@babel/core` 7 would give Next, Nuxt and `styled-jsx` their old peer back. It costs a root dependency upstream doesn't have, and it moves every Babel 7 package to newer patches, where leaving it out moves six packages' links.
- **The plugin's scope.** `**/packages/angular/**` and `**/fixtures/*/angular*.ts`, through `transformFilter`. The same two patterns are in `oxc.exclude`, so Vite's own transform leaves them to Angular's compiler, as Solid and React each take their own `.tsx`.
- **`oxc` is set in the config.** The plugin's `config` hook returns `oxc: config.oxc ?? false`, which turns Vite's TypeScript transform off for every framework unless the config sets `oxc` itself.
- **`tsconfig.angular.json` emits.** It sets `noEmit: false`, because the base tsconfig's `noEmit: true` makes the plugin serve an empty module with no error. `rewriteRelativeImportExtensions` then lets fixtures keep importing `tests/fixtures/page.ts` by its `.ts` name. It includes `src/fixtures/*/angular*.ts`, which `tsconfig.json` now excludes.
- **Type check.** The playground's `typecheck` ends with `ngc --noEmit -p tsconfig.angular.json`, with `strictTemplates`.
- **Ahead-of-time, so no JIT fallback.** The served module holds `ɵɵdefineComponent`, on the dev server and in the build. `jit: true` stays the fallback the plan names, unused.
- **Zoneless with no provider.** `@angular/core` 22.3.0 documents zoneless as the default from v21, so the fixture calls `createApplication()` bare.
- **The fixture is empty on purpose.** P1.4 writes the Tabs fixture. Until then its specs fail on `angular` at `open()`, waiting for the "Before" button.

5. **Known gaps.**
   - **What drifted in the lockfile.** Comparing what each of upstream's packages links to, before and after: six Babel 7 packages (`generator`, `template`, `traverse`, `helpers`, `helper-module-imports`, `helper-module-transforms`) now link to `@babel/types` 7.29.11 and to `parser`, `traverse` and `generator` 7.29.12, where upstream had 7.29.8 to 7.29.10, while `@babel/core` 7.29.7 keeps the older ones. `ast-kit` and `ast-walker-scope` moved from Babel 8.0.10 to 8.1.3, and `oxc-walker` from `@oxc-project/types` 0.152.0 to 0.158.0. Since P0.3, `@solidjs/vite-plugin` and `styled-jsx` link their optional `@babel/core` to 8.1.0. Vite's optional `sass` and `sass-embedded` peers resolve. Each is a patch, or an optional peer nothing here uses, inside build tooling, and every command above ran on this lockfile. No version changed for Vite, rolldown, vitest, esbuild or any framework.
   - **The overrides repeat two pins:** the catalog's Vite range and the root's rolldown version. When upstream moves either, the override moves with it or goes, and the resolution that follows can stop on another locked version, which needs the owner's go-ahead like the first two.
   - **Angular's builder runs on a Vite and rolldown it doesn't pin.** Only its compile API is in use here, through the plugin. A later task that needs more of it should check this first.
   - **The plugin adds `style` to `resolve.conditions`** and its own step to dependency optimizing, for every framework. The Tabs runs and the `react` project above are the evidence that neither matters. The other four projects ran only their Tabs specs.
   - **The built playground's `/__ssr` route fails on this machine,** with and without Angular. Nothing here shows whether the plugin affects the built SSR bundles of Vue, Svelte and Solid, beyond their builds passing. That needs a run on Linux.
6. **Questions.** Should the exemption list live upstream too? Upstream's own lockfile can't be resolved again without it.
