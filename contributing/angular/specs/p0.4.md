# P0.4: Angular in the playground

**Blocked, and the next step is your decision.** The Analog plugin can't load without `@angular/build`, and the workspace's `trustPolicy: no-downgrade` refuses every install that adds it. The playground is unchanged.

## What blocks it

- **The plugin needs `@angular/build`.** `@analogjs/vite-plugin-angular` 2.9.7 calls `require("@angular/build/private")` as it loads, for Angular 18 and later (`src/lib/utils/devkit.js`). Its `package.json` marks that peer optional, but nothing in the plugin runs without it.
- **The install is refused.** Adding `@angular/build` 22.3.0 ends in `ERR_PNPM_TRUST_DOWNGRADE` for `semver@6.3.1`, reached through `eslint-plugin-react-hooks` and `@babel/core@7.29.7`.
- **The refusal predates Angular.** `semver@6.3.1` is already in the committed lockfile. The policy fires when pnpm resolves a subtree that holds such a package again. On the untouched `1df723cb`, deleting the lockfile and running `pnpm install --lockfile-only` fails the same way, first on `chokidar@4.0.3` under `svelte-check`. So an install passes here only while it leaves those subtrees alone.

Each row starts from the P0.3 lockfile:

| Change                                                                                           | Exit |
| ------------------------------------------------------------------------------------------------ | ---- |
| Playground: `@angular/core`, `common`, `platform-browser`, `rxjs`, `@ui-sdk/angular`, the plugin | 0    |
| The same, and `@angular/compiler-cli` in the playground                                          | 1    |

One run with `@angular/build` in the playground did resolve, after an install that Windows aborted halfway had left the lockfile partly updated. It can't be repeated from a clean tree, so it only served to measure the drift below.

## What the plugin does in a shared config

Read from the plugin's source, since it was written for an Angular-only app:

- **It turns off Vite's TypeScript transform.** Its `config` hook returns `oxc: config.oxc ?? false`, so every `.ts` and `.tsx` of the other frameworks goes untransformed unless the config sets `oxc` itself.
- **It takes every `.ts` outside `node_modules`.** `transformFilter(code, id)` narrows that. It isn't an `enforce: "pre"` plugin, so Vite's own transform sees an Angular file first unless `oxc.exclude` names it.
- **It adds `style` to `resolve.conditions`,** with Vite's default client conditions after it.
- **It changes dependency optimizing:** it includes `rxjs` and `rxjs/operators`, excludes `@angular/platform-server`, and adds a rolldown plugin that links Angular's packages.
- **In a build it handles every `.js`.** It links files under `fesm20*`, and for the rest drops the source map and the `sourceMappingURL` comment. It defines `ngDevMode`, `ngJitMode`, `ngI18nClosureMode` and `ngServerMode`.

## What `@angular/build` does to the lockfile

Measured in the one run that resolved:

- 301 more packages. It pins `vite` 8.3.8 and `rolldown` 1.3.1, beside the catalog's 8.3.3 and the root's 1.2.12.
- pnpm then put Vite 8.3.8 and rolldown 1.3.1 or 1.2.19 under `vitest`, `nuxt`, `@nuxt/kit`, `unplugin`, `vue-router`, `fumadocs-mdx` and a dozen more. The other adapters' unit tests would run on a Vite the repo doesn't pin.
- Vite's optional `sass` and `sass-embedded` peers resolve, and Nuxt's `rolldown` peer (`~1.2.1`) goes unmet.

Pinning `@angular/build`'s `vite` and `rolldown` with `overrides` would contain this, but an override makes pnpm resolve everything again, which the policy refuses.

## Options

1. **Exempt the locked versions in `pnpm-workspace.yaml`,** with `trustPolicyExclude` for `semver@6.3.1` and whatever else a resolution names, like `chokidar@4.0.3`. Each is a version the lockfile installs today, so the exemption admits nothing new. It unblocks `@angular/build`, the `overrides` above, and the root Babel 7 pin that would undo P0.3's Babel 8 drift.
2. **Pass `--trust-policy-exclude` by hand** on each install that changes the lockfile. Nothing in the repo changes, and every later task that adds a dependency has to know.
3. **Replace the Analog plugin with a small Vite plugin in the repo** on `@angular/compiler-cli`, which P0.3 installed without trouble. No `@angular/build`, no second Vite, and it touches only Angular's files by construction. It departs from the plan and isn't prototyped.
4. **Build the Angular fixtures in a project outside the workspace,** the plan's second fallback, with its own lockfile. The shared lockfile stays as it is, and the playground gains a second build to load.

## Planned, not built

These hold for options 1, 2 and 4:

- **Scope.** `**/packages/angular/**` and `**/fixtures/*/angular*.ts` for `transformFilter`, and the same two patterns in `oxc.exclude`, so each compiler takes its own files as Solid and React do.
- **`tsconfig.angular.json`** includes `src/fixtures/*/angular*.ts`, `tsconfig.json` excludes it, and `typecheck` gains an `ngc --noEmit` step.
- **One declaration of the compiler.** `@angular/compiler-cli` stays in `packages/angular` only, since a second one in the playground trips the policy too. The workspace is hoisted, so the plugin still finds it.
- **JIT fallback.** `jit: true`, if ahead-of-time compiling fails beside the other plugins.
