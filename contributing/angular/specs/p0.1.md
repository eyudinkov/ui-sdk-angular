The fork has an `angular` integration branch, cut from a tree that installs, type-checks and builds untouched.

## Settled

- **Integration branch.** `angular`, cut from the fork's `main` at `1df723cb`. That is upstream `main` at `2f1b22c8` (`0.1.0-beta.16`) plus two fork commits: the `angular-developer` skill and the agent-skills plugin setting.
- **Task branches.** `angular-<id>-<slug>`, like `angular-c24-menu`. The plan's `angular/<id>-<slug>` can't exist beside `angular`: git keeps a branch as a file, and `angular` would have to be a folder too.
- **Upstream.** The `upstream` remote is `https://github.com/vercel-labs/ui.git`. The plan scanned `a349d52`, one release back, so its line numbers can be a few lines off.
- **Rebase rhythm.** The coordinator rebases `angular` on `upstream/main` at each gate, and before a wave starts when upstream has released since the last rebase. After the rebase come `pnpm install`, `pnpm typecheck`, `pnpm build` and `pnpm test:pr --base upstream/main`, then `git push --force-with-lease origin angular`.
- **Linear history.** A task branch lands on `angular` without a merge commit, so a rebase replays one commit per change and a conflict in a shared file stays inside the commit that made the edit. An open task branch moves onto the new `angular` between review rounds, never during one.

The settings that make the gates run on Windows, none of them in the repo:

- **LF checkouts.** `git config core.autocrlf false` and `git config core.eol lf` in the clone, then a fresh checkout. Prettier checks for LF, and a CRLF checkout fails all 8,000 files.
- **Git Bash for package scripts.** `npm_config_script_shell="C:\Program Files\Git\bin\bash.exe"` in the environment of any command that runs one. The playground's scripts use `${PLAYGROUND_PORT:-5300}` and `NODE_ENV=development vite build`.
- **Windows' `tar` first.** `PATH="/c/Windows/System32:$PATH"` for `check:packages`, run as `pnpm exec node scripts/check-packages.mjs`. Git's `tar` reads `C:` as a host name.
- **Junctions for folder links.** `check:packages` links its peers with `symlinkSync(…, "dir")`, which needs Developer Mode. This preload, passed to Node with `--import`, makes a junction of each:

```js
import fs from "node:fs"
import { syncBuiltinESMExports } from "node:module"

const symlinkSync = fs.symlinkSync
fs.symlinkSync = (target, path, type) =>
  symlinkSync(target, path, type === "dir" ? "junction" : type)
syncBuiltinESMExports()
```

`pnpm lint` and `pnpm size` have no such setting: their scripts compare paths as strings. Until they run on Linux, a task passes them when it adds no finding to the baseline's.
